# PhotoSys

PhotoSys 是一个使用 Tauri 2、Vue 3、TypeScript 和 Rust 的桌面应用，用于浏览、收藏、查重和归档本地照片与视频。

## 界面与外观

左侧导航将媒体库、人物、相册放在「浏览」分组，将归档、重复文件和相似照片放在「整理」分组。较窄窗口使用图标导航，可悬停查看名称；更窄窗口点击顶部菜单展开导航。

导航底部可选择浅色、深色或跟随系统，默认跟随系统，选择会保存在当前设备。外观切换不影响进行中的扫描、归档和分析任务。媒体网格保留文件名、日期、位置与收藏，完整信息在详情查看；宽窗口中大图和信息栏并排显示，窄窗口中上下排列。

运行 `npm run test:theme` 检查主题跟随、保存与存储异常处理。界面验收记录及桌面回归清单见 [界面改版验证](docs/ui-redesign-validation.md)。

## 便携媒体库

将 Linux x64 的 `PhotoSys.AppImage` 放到相册根目录。在文件属性中授予执行权限，或运行 `chmod +x PhotoSys.AppImage`，然后双击。启动时，PhotoSys 优先打开 AppImage 同目录中已有的媒体库，然后尝试恢复上次手动选定的目录。两处都没有可用媒体库时，在「媒体库」中点击「选择目录」。在外部添加、删除或改名文件后，点击「刷新」更新列表。

如果 Linux 环境无法挂载 AppImage，可在相册目录运行 `APPIMAGE_EXTRACT_AND_RUN=1 ./PhotoSys.AppImage`。

媒体库默认按拍摄日期从新到旧排列，每页显示 24 项。搜索框按文件名或相对路径进行不区分大小写的包含匹配，可与类型、日期范围、日期未知和收藏筛选叠加使用。输入停止 250 毫秒后更新结果，中文输入法组词期间不查询。可按拍摄日期、名称或文件大小升降序排序，日期未知始终排在日期排序末尾。更改搜索、筛选或排序后回到第一页；刷新当前目录保留条件，更换目录恢复默认条件。搜索和排序条件不跨应用重启保存。

可以在应用内预览 JPG/JPEG、PNG、WebP、TIFF、HEIC/HEIF 和 `.livp` 封面。支持解码的 MOV、MP4、M4V、3GP、MKV 和 WebM 视频会显示首帧缩略图，点击可查看大图。详情中的「上一项」「下一项」或左右方向键沿当前结果顺序跨页浏览全部媒体，首尾不循环，Esc 关闭。焦点位于视频播放控件时，方向键由播放器处理。关闭详情后，列表定位到最后查看项。照片和视频都可以用系统默认应用打开；在 `.livp` 详情中点击「播放实况」，可在应用内播放包内的 MOV 或 MP4，切换媒体会停止播放。

图片详情中可点击「向左旋转 90°」「向右旋转 90°」，自动保存浏览方向并同步列表缩略图。方向在图片已有的 EXIF 校正基础上叠加，连续同向旋转四次恢复原方向。支持所有可预览照片和 `.livp` 静态封面，视频及实况视频播放保持原方向。旋转记录按相对路径保存在 `.photosys/library.sqlite` 中，刷新、重启和整体搬迁相册后保留，不修改原图片；单独移动或重命名图片后不迁移记录。旧数据库首次保存旋转时自动增加旋转表，只读媒体库仍可浏览，但无法保存方向，保存失败会保留原角度。

详情中可点击「在文件管理器中显示」定位原文件，定位失败时尝试打开所在文件夹并提示无法选中文件；也可点击「复制完整路径」复制系统格式的绝对路径。文件在扫描后被移动、替换或删除时，需要刷新媒体库后重试。无法准确转换为文本的路径不会被复制。从媒体库切换到归档、查重或相似照片时，会带入当前目录。

手动选择目录时，PhotoSys 会读取其中已有的 `.photosys/library.sqlite`，或在数据库缺失时创建并初始化它。初始化失败时可查看错误并重选目录。已有有效数据库的只读目录可以浏览，初始化和保存收藏需要写入权限。

搬家时先关闭 PhotoSys，再复制整个相册目录，包括隐藏目录 `.photosys` 和随相册存放的 AppImage。直接启动搬迁后的 AppImage，或在安装版中选择搬迁后的目录。收藏按相对路径保存，整个相册换位置后仍可使用。单独移动或重命名媒体文件后，收藏仍对应原相对路径。

## 主题相册

在左侧打开「相册」，为一次出游、活动或情景创建命名相册，例如“周末露营”“杭州之旅”。名称去除首尾空白后必填，最多 80 个字符，允许同名。相册列表显示当前可用的照片与视频数量，自动使用其中可预览的最新媒体作为封面；空相册也可保留。

在「媒体库」点击「批量选择」，逐项勾选或「全选当前页」，再点击「加入相册」，选择已有相册或新建后加入。勾选跨页保留，改变搜索、筛选、排序、页面或当前相册后清空；刷新、更换目录及恢复数据库也会清空。保存失败保留勾选和输入，可直接重试。同一媒体可加入多个相册，重复加入不会产生重复成员。照片、实况照片和视频均支持，不移动或修改原文件。

进入相册可按文件名、类型、日期及收藏筛选和排序，复用媒体库的预览、连续浏览、收藏及旋转。在「管理相册」中改名或删除相册，也可批量将成员「从此相册移出」。移出或删除相册仅删除对应归类记录，原文件和其他相册归属保留。点击「去媒体库添加」会预设目标相册，添加后可直接返回。

相册按相对路径保存在 `.photosys/library.sqlite`，刷新、重启、整体搬迁及数据库备份恢复后保留。单独删除或改名的媒体不再计入相册数量、封面和浏览结果，恢复到原路径并刷新后可再次显示。旧库首次编辑相册时自动增加相关表；只读库可浏览已有相册，不能编辑。首版仅手动归类，不提供自动活动识别、嵌套相册、自定义封面或相册内 AI 搜索与地图。

验证记录见 [主题相册验证](docs/albums-validation.md)。运行 `npm run test:albums` 检查跨页选择与名称规则。

## 数据库备份与恢复

在「媒体库」或「人物」页面的目录工具栏打开「数据库备份与恢复」，点击「备份当前相册」，选择 ZIP 保存位置。备份包含 `.photosys/library.sqlite`（收藏、旋转、位置缓存及主题相册）、`ai.sqlite`（AI 搜索索引）及 `people.sqlite`（人物名称、人脸归属、纠错、忽略和撤销记录）；尚未建立的可选索引不会创建。快照包含 SQLite WAL 中已提交的数据。备份在全部成功后才发布，失败不会覆盖已有备份文件。

点击「选择备份文件恢复」，校验后查看备份时间、来源相册和数据库清单，确认目标目录及回退副本位置，再点击「确认覆盖并恢复数据库」。默认恢复到当前相册，也可另选相册目录；没有打开相册、数据库损坏无法打开或迁移到新目录时均可使用。恢复会完整覆盖三个数据库，备份中缺失的 AI 或人物索引会清除目标对应旧库。媒体按相对路径匹配，单独改名或移动的照片需要重新建立对应索引。

恢复前，原数据库和 SQLite 辅助文件原样保存在目标相册 `.photosys/restore-backup-*` 内，损坏文件也会保留。写入失败时自动回滚；应用意外退出后，下次打开该相册会先处理未完成的恢复日志。回滚失败时会显示回退目录，请保留该目录和 `restore-journal.json`，重新打开相册重试。恢复成功后自动重新读取相册，读取失败会单独提示，原始媒体不受影响。

回退副本不会自动清理。需要手动回退时，先关闭 PhotoSys，按副本中的 `recovery.json` 清单，将原数据库及其 `-wal`、`-shm`、`-journal` 文件复制回 `.photosys`，同时删除清单中不存在的上述三个数据库及辅助文件；不要覆盖或删除其他文件。确认不再需要回退后可删除对应 `restore-backup-*` 目录。

数据库 ZIP 不包含照片视频、模型、离线地图、全局设置和相似照片缓存，完整搬家仍需复制原始媒体。备份与恢复期间会停止后台索引并暂时禁止数据库操作，结束后恢复正常增量分析。操作时请关闭访问同一相册的其他 PhotoSys 进程。

## 归档照片与视频

打开 PhotoSys，选择源目录和目标目录，点击「开始复制」。应用递归扫描源目录，按文件名里的日期或媒体内嵌拍摄时间，将原文件复制到目标目录的 `yyyy/yyyy-MM/` 下。没有可用日期的媒体进入 `其它/`。目标目录中同名且内容相同的文件会跳过，同名但内容不同的文件会以 `名称_1.扩展名` 等名称保存。

每次任务结束后，目标目录根目录会生成一份 `复制说明_yyyyMMdd_HHmmss.txt`。界面会显示本次统计和说明文件路径。

## 查找重复文件

打开「重复文件」，选择目录后开始扫描。应用递归检查所有类型的普通文件，跳过符号链接和 `.photosys` 数据目录，仅将完整内容完全相同的文件列为重复。扫描按大小分组，对超过 192 KiB 的候选文件先读取首、中、尾各 64 KiB 预筛，再计算完整 SHA-256 并逐字节确认。扫描进度显示当前阶段、文件数、累计内容读取量、当前文件及耗时；可随时点击「取消扫描」，取消完成后可立即重扫。

结果显示重复组数、文件数和可整理副本的逻辑大小。可按文件名或相对路径搜索，结合照片与实况照片、视频、其他文件类别筛选，并按副本逻辑大小、单文件大小或文件数量降序排列。搜索输入停止 250 毫秒后更新，中文输入法组词期间不查询；同一文件同时满足搜索与类别时，展示它所在的完整重复组。重复组、组内文件、问题明细及处理明细每页 25 项，展开组后可手动勾选。支持的照片、视频首帧和实况照片封面可预览，也可定位原文件或复制完整路径。

展开「保留规则」可输入优先保留子目录的相对路径，例如 `精选/原片`，并选择最靠近根目录、修改时间最早或修改时间最新。先优先指定目录，再应用组内规则，相同条件按相对路径排序；修改时间不等于拍摄时间。点击「按规则勾选当前筛选结果」会替换全部已有勾选。硬链接全部保留，每组至少保留一份；其他正常副本仍可勾选。

手动勾选跨页、搜索、类别及排序切换保留，界面提示筛选范围外的已选数量。点击「移到回收站」后，可分页查看全部待移除项和保留项，清理包含筛选范围外的勾选。确认绑定当前勾选版本，过期确认会被拒绝；每次移除前重新核验原文件。成功项移出结果，有效失败项保留勾选便于重试，文件已变化的组必须重扫。移除的文件可从系统回收站恢复，清空回收站后才可能释放实际磁盘空间；返回媒体库后点击「刷新」更新列表。

结果和勾选只保存在当前会话，重新扫描或更换目录后清空，不新增持久哈希缓存或数据库迁移。验证结果和性能取舍见 [重复文件优化验证](docs/duplicates-validation.md)。

## 查找相似照片

打开「相似照片」，选择目录后开始扫描。应用递归查找 JPG/JPEG、PNG、WebP、TIFF 和 HEIC/HEIF，可按「同图变体」或「疑似连拍」筛选结果。展开相似组后，可任选两张照片并排查看预览和文件信息。可在组内手动勾选照片，确认后批量移到系统回收站，并查看逐项处理结果。每组至少保留一张，代表图也可勾选，硬链接照片保留；组内翻页会保留勾选，切换相似组或筛选时清空勾选。删除代表图后会重新匹配组内剩余照片，必要时拆分相似组。移除的照片可通过系统回收站恢复；返回媒体库后点击「刷新」更新列表。

同图变体包括压缩、缩放、格式转换和轻微调色后的版本。疑似连拍还会检查 EXIF 拍摄时间，要求相差不超过 5 秒。复扫会使用本地 SQLite 索引复用未变化照片的图像特征。暂未支持的照片格式和读图失败会列在「问题明细」中。

## 本地 AI 内容搜索

在媒体库打开「AI 搜索设置」，选择模型及安装目录，再点击「下载并安装模型」。内容搜索提供三种模型：

| 模型 | 下载量 | 使用建议 |
| --- | --- | --- |
| Chinese-CLIP B/16 · 均衡版（默认） | 约 755 MB | 资源开销较低，适合日常中文照片搜索 |
| Chinese-CLIP L/14 · 增强版 | 约 1.63 GB | 公开中文检索测试整体更好，分析更慢、更占内存 |
| Chinese-CLIP L/14@336px · 高分辨率版 | 约 1.63 GB | 更高输入分辨率，计算开销进一步增加 |

每个模型的设置中提供用途、限制、下载大小、CPU 开销、本机小样本性能、许可和来源说明；公开测试成绩不等于家庭相册准确率。模型按独立子目录存放，多个相册可以共用。应用记住所选目录，换电脑或路径失效后需要重新选择。更换目录不会搬动或删除旧模型。

默认通过第三方 HF-Mirror 镜像下载，失败后尝试 Hugging Face 原源，也可手动切换。下载支持取消、重试和断点续传；服务端不支持续传时重新下载对应文件。所选模型固定版本的全部文件通过大小、SHA-256 校验和本地推理自检后才完成安装。修复安装会保留旧目录为 `.photosys-model-backup-*`，确认新模型可用后可自行清理备份。

选择和安装不会改变当前模型；已安装的其它模型需要点击「使用此模型」，阅读当前相册待处理数量和影响后确认。选择对所有相册统一生效。切换时停止该类分析任务，切换后提示手动「重建内容索引」；刷新、重启或打开其它相册不会自动开始新模型的首次重建。重建前仅搜索与当前模型兼容的已索引照片，文件名浏览与搜索继续可用。重建逐批保存，可停止后继续；切回旧模型时已被覆盖的特征需要重新计算。原照片、收藏、浏览方向和旧模型文件保留。同模型换目录可复用有效索引。

模型就绪后，首次手动点击「建立索引」。之后打开或刷新相册时，自动分析新增、修改及旋转方向变化的照片。处理过程不锁定照片浏览；可点击「停止索引」，已保存部分会保留。失败项列在「AI 索引问题」，手动「更新索引 / 重试失败项」会重新尝试。只读相册可搜索已有有效索引，不能建立或更新索引。

将「搜索方式」切换到「照片内容」，输入“海边日落”“雪地里的小狗”等描述，再按回车或点击「搜索照片」。中文输入法组词时不会提交查询。结果按内容相关度排列，最多 200 张，每页 24 张，可结合拍摄日期、日期未知及收藏筛选；输入中的日期不会自动转换为筛选条件。索引未完成时只搜索已保存部分，并显示覆盖情况。文件名模式保持原有搜索、筛选与排序行为。

列表翻页和地图会复用同一查询的排名。筛选条件、收藏、旋转或已保存的索引变化后，下次查询会重新匹配。

AI 索引保存在相册的 `.photosys/ai.sqlite`，使用相对路径，可随整个相册目录搬迁。索引不修改原照片、收藏或现有相似照片缓存。支持 JPG/JPEG、PNG、WebP、TIFF、HEIC/HEIF，以及 `.livp` 静态封面；沿用现有解码大小限制。首版不分析视频、不识别人名或图片文字。索引表示内容相似程度，不保证每张返回照片都符合描述。

Windows x64 安装包内置 DirectML。内容搜索和人物分析默认优先使用支持 DirectX 12 的 NVIDIA、AMD 或 Intel 显卡。GPU 运行库或会话不可用时会自动回退到 CPU，在模型设置中可查看原因。两处模型设置共用「推理设备」选项，可选择「仅 CPU」，重启后生效。切换推理设备可继续使用原有模型和已建索引。macOS 和 Linux 使用 CPU。

模型安装后，建立索引和搜索可以完全断网。AI 运行时随软件打包，已关闭运行时遥测；照片、文件路径和搜索描述均不上传。GPU 加速使用系统显卡驱动。模型与原始资料的来源、固定版本和许可见 [AI 模型说明](scripts/AI-MODEL-NOTICES.md)。

无网络的电脑可使用「导入离线模型包」。在已安装模型的电脑上，用以下开发工具导出兼容 ZIP，再复制到目标电脑导入；ZIP 包含对应模型需要的 ONNX 文件、词表（内容搜索模型）、许可和模型标识；导入前选择匹配的模型，导入执行相同的校验与自检。原有不含模型标识的离线包仍通过固定文件校验兼容。

```sh
python3 scripts/package-ai-model.py /path/to/models/chinese-clip-vit-b16-fp32-v1 /path/to/photosys-model-v1.zip
# 导出其它模型时指定设置中对应的模型 ID
python3 scripts/package-ai-model.py --model-id chinese-clip-vit-l14-336px-fp32-v1 /path/to/models/chinese-clip-vit-l14-336px-fp32-v1 /path/to/photosys-model-l14-336px.zip
```

## 本地人物相册与家庭时间线

在顶部打开「人物」，沿用当前媒体库目录。在「人物模型设置」中可选择 YuNet + SFace 轻量版（默认，约 39 MB）或 YuNet + AuraFace 大模型版（约 261 MB），也可以导入对应离线 ZIP；内容搜索模型与人物模型独立管理，原有内容搜索设置继续有效。人物模型未单独指定目录时，默认使用已选的 AI 模型目录。安装后，点击「建立人物索引」。仅首次需要手动启用，此后打开或刷新相册会增量分析，处理期间可以浏览，可停止后继续，并重试失败项。

SFace 和 AuraFace 均默认开启保守自动分组：高相似度人脸归入已有分组，无匹配对象时创建未命名人物；存在歧义、小尺寸或无有效特征的人脸保留在「待整理」。给整组命名即可创建人物相册，不必逐张输入名称。已建立索引的相册在下次打开或更新分析时，会复用有效特征补充分组。家庭相册准确率尚未通过独立标注验收，初始参数不代表准确率保证。

在「待整理」选择本页人脸后，点击「查看归组建议」。每张人脸最多显示三个候选人物。不同照片中的所选人脸有共同候选时，可以一次归入该人物，整批作为一次人工操作撤销。只读相册可以查看建议。

进入人物相册，在「修改分组 / 管理人物与人脸」中批量选择误分的人脸，移入已有人物或拆成新人物，也可改名、合并重复人物、忽略误检及恢复已忽略的人脸。人脸标示「自动归入」或「人工指定」；人工归属和忽略优先，后续自动分析不会覆盖。最近 100 次人工操作可依次撤销，重启后保留。照片详情也提供「修改分组」入口。

人物相册默认按拍摄日期从早到晚排列，可切换顺序，按年月导航、指定日期范围或仅看收藏；日期未知单列。同一照片含多张该人物的人脸时只显示一次。时间线沿用媒体库的拍摄日期，不推断年龄、亲属关系或事件。当前仅处理照片与实况静态封面，不分析视频。

人物名称、归属、纠错及人脸特征保存在 `.photosys/people.sqlite`，不修改原照片，可随整个相册目录搬迁。更换人物模型后，手动点击「重建人物索引」重新计算特征。同一照片内容、方向和检测流程下能唯一对应的人脸保留 ID、人工归属、忽略、纠错及撤销记录，只更新特征；无法可靠对应时进入待核对。有效的人工人物相册仍可浏览。AuraFace 沿用相同 YuNet 检测器，仅替换识别权重，不安装其它 InsightFace 模型，两种模型各自使用对应特征版本的自动分组参数；未知模型版本不自动归组。

文件被替换或旋转后，不自动把旧身份套用到新内容：旧人工标注出现在待整理中，提示核对当前人脸，旧标注可忽略。删除文件后不再显示其照片；单独移动或改名文件不迁移标注。只读相册可查看已有结果，不能分析或编辑。模型安装后可完全断网使用。

导出人物离线模型包：

```sh
python3 scripts/package-ai-model.py --kind people /path/to/yunet-sface-fp32-v1 /path/to/photosys-people.zip
```

人物数据库在需要写入时自动升级到版本 2；已有旧库可直接读取，只读模式不执行升级。旧版 PhotoSys 无法读取升级后的版本 2 人物数据库。

实现验证、性能范围和自动归组准确率验收条件见 [人物相册验证记录](scripts/PEOPLE-VALIDATION.md)，模型来源与许可见 [人物模型说明](scripts/PEOPLE-MODEL-NOTICES.md)。

## 开发环境

安装 Node.js 24 LTS 和 npm，再通过 [rustup](https://rustup.rs/) 安装 Rust stable。安装后重新打开终端，确认 `node --version`、`npm --version` 和 `rustc --version` 可用。

**Windows** 安装 Microsoft Edge WebView2 Runtime 和 Visual Studio Build Tools 的「使用 C++ 的桌面开发」工作负载，包含 MSVC x64/x86 工具、Windows SDK 和 Visual C++ Redistributable 最新组件。用 `rustup default stable-msvc` 选择 Rust 工具链，安装后重新打开终端。

**Debian 13 / Ubuntu 24.04** 在宿主机安装 Tauri 开发和打包依赖。

```sh
sudo apt-get update
sudo apt-get install -y build-essential ca-certificates curl wget file pkg-config \
  libwebkit2gtk-4.1-dev libxdo-dev libssl-dev libayatana-appindicator3-dev \
  librsvg2-dev gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
  nasm patchelf xdg-utils
```

**macOS** 运行 `xcode-select --install` 安装命令行开发工具。若要构建供 Apple Silicon 和 Intel 共用的安装包，安装两个 Rust 目标。

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
```

各系统完整安装步骤见 [Tauri 平台依赖](https://v2.tauri.app/start/prerequisites/)。

## 运行和打包

首次启动前需要准备 FFmpeg、ONNX Runtime 和 PMTiles。准备脚本会校验下载内容并复用构建或下载缓存。

**Windows x64** 安装 [MSYS2](https://www.msys2.org/) 和 Python 3.11 或更新版本。打开 **MSYS2 UCRT64** 终端，进入项目根目录，执行以下命令生成项目专用的 FFmpeg。

```sh
pacman -S --needed curl diffutils make perl mingw-w64-ucrt-x86_64-gcc \
  mingw-w64-ucrt-x86_64-nasm mingw-w64-ucrt-x86_64-pkgconf
bash scripts/build-media-codec.sh
```

回到 **PowerShell**，在项目根目录准备其余依赖并启动 Vite 和 PhotoSys 桌面窗口。

```powershell
npm.cmd ci
python scripts/prepare-windows-runtime.py
python scripts/prepare-ai-runtime.py
python scripts/prepare-offline-maps.py
npm.cmd run tauri -- dev
```

**Linux 和 macOS** 安装 Python 3.11 或更新版本。macOS 另需执行 `brew install pkgconf nasm`。在项目根目录执行以下命令。

```sh
bash scripts/build-media-codec.sh
python3 scripts/prepare-ai-runtime.py
python3 scripts/prepare-offline-maps.py
npm ci
npm run tauri -- dev
```

关闭开发进程后，可运行 `npm run tauri -- build -- --locked` 构建本机安装包。Windows PowerShell 中使用 `npm.cmd`。

单独检查前端类型和生产构建，以及 Rust 测试。

```sh
npm run build
cargo test --locked --manifest-path src-tauri/Cargo.toml
```

在 macOS 上先运行 `bash scripts/build-media-codec.sh universal-apple-darwin` 和 `python3 scripts/prepare-ai-runtime.py --universal`，再用 `npm run tauri build -- --target universal-apple-darwin -- --locked` 构建通用包。通用包分别提供 Apple Silicon 和 Intel 的 CPU 运行时。本机打包产物位于 `src-tauri/target/release/bundle/`，指定 `--target` 后位于 `src-tauri/target/<target>/release/bundle/`。

AI 模型实测方法及当前验证范围见 [AI 搜索验证记录](scripts/AI-SEARCH-VALIDATION.md) 和 [模型选择验证记录](scripts/MODEL-OPTIONS-VALIDATION.md)。

## GitHub Actions

完整操作步骤见 **[三平台打包与 Release 发布教程](docs/packaging.md)**，包含手动打包、下载安装、修改版本发新版、本地打包和失败重试。

将项目推送到启用了 Actions 的 GitHub 仓库。推送到 `main`、打开或更新 PR 时，三个平台会并行运行常规测试并打包。工作流进入默认分支后，也可以在 **Actions → Desktop builds → Run workflow** 手动触发；`full_ai_validation` 默认关闭，勾选后额外下载五套模型并运行完整 AI 验证。在运行详情页的 **Artifacts** 或摘要链接下载对应产物，保留 30 天。

推送与项目版本一致的 `v主版本.次版本.修订号` 标签（例如 `v0.1.1`）后，工作流会等待三平台构建及 Intel macOS 运行时检查全部成功，将四个安装包、媒体解码器源码归档和 `SHA256SUMS` 上传至草稿，再自动公开发布 GitHub Release。上传失败保留草稿，重跑会更新同一草稿；已公开版本不覆盖。手动运行、main 和 PR 构建只提供 Artifacts。

| Artifact | 构建环境 | 文件 |
| --- | --- | --- |
| `PhotoSys-windows-x64` | Windows Server 2025 x64 | 未签名的 Windows x64 NSIS `.exe` |
| `PhotoSys-linux-x64` | Ubuntu 24.04 x64 | Linux x64 `.deb` 和 `.AppImage` |
| `PhotoSys-macos-universal` | macOS 15 arm64 | 通用 `.dmg`，包含 `arm64` 和 `x86_64`，采用 ad-hoc 签名 |

安装后打开 PhotoSys，用临时目录试复制几张照片，检查归档子目录和复制说明，再用相同目录运行一次并核对重复跳过数量。Windows 和 macOS 的内部测试包可能触发 SmartScreen 或 Gatekeeper 提示。

各构建产物附带 `media-codec-sources.tar.gz`，其中包含媒体解码器的对应源码和构建脚本。安装包中包含许可文本。详见 [媒体解码器许可](scripts/MEDIA-CODEC-NOTICES.md)。

## 拍摄位置与离线地图

媒体库会读取照片、视频和 `.livp` 的内嵌 GPS，在卡片中显示地点，详情中显示行政区地址和 WGS84 经纬度。实况照片优先使用静态照片的位置；没有 GPS 或位置标签损坏的文件显示「位置未知」。原文件不会被修改。中国行政区地址在本机解析，海外和数据未覆盖的地区仍显示坐标。内置行政区数据是固定历史快照，部分地点只包含省级或原始语言名称，不提供街道门牌地址。

在筛选栏选择「全部位置」「有位置」或「位置未知」，也可以展开「位置地图」。点击聚合点放大，点击单点筛选该坐标的媒体；点击「框选」并在地图上拖出矩形，查找范围内的照片、视频。平移、缩放不会改变结果。位置条件可与日期、类型、文件名和收藏组合，人物照片、AI 内容搜索也支持；AI 搜索在位置筛选后取前 200 张。地图统计包含当前结果的全部分页。更换媒体库会清除位置条件，刷新同一目录会保留。

展开地图下方「离线地图包」，搜索省市区或使用框选区域下载街道底图。首次下载需要联网，默认到 z15；完成后，地图、中文字体、样式和地址解析全部离线使用。还可以导入 PMTiles v3、Protomaps v4 图层结构的地图包，选择保存目录，或删除不再需要的包。更换目录不搬动旧地图包；重叠区域优先使用最新安装的包。取消或下载失败不会替换已有地图，重启后可恢复未完成区域并重新下载。无街道地图时显示内置世界概览与媒体点位。

位置缓存保存在相册 `.photosys/library.sqlite`，按相对路径、文件指纹、解析器和地址数据版本复用。文件变化后会重新读取；只读相册无法保存缓存时使用内存结果。数据、字体和地图工具来源、快照限制及许可见 [离线地图说明](scripts/OFFLINE-MAPS-NOTICES.md)。

本地开发或打包前运行 `python scripts/prepare-offline-maps.py` 准备固定版本的 PMTiles 工具；macOS 通用包使用 `--universal`。GitHub Actions 已包含准备步骤。行政区与前端底图资源已随源码提供，日常构建无需重新下载地理数据。
