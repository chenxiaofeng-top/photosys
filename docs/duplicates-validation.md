# 重复文件优化验证

验证日期：2026-11-19。

## 实现与接口

- 扫描依次执行大小分组、抽样预筛、完整 SHA-256、逐字节确认。超过 192 KiB 的候选文件抽样首、中、尾各 64 KiB；抽样不作为相同内容的判定依据。顺序读取，未引入持久哈希缓存或数据库迁移。
- `scan_duplicates(directory, scanId, progress)` 返回 `finished + summary` 或 `cancelled`。进度含阶段、发现数、处理数、阶段总数、累计内容读取字节、当前文件和耗时，约每 200 ms 更新；每个读取块都检查取消。取消标志独立于结果会话锁，并在工作线程启动前注册，避免立即取消丢失。
- `duplicate_groups` 返回当前页组摘要及全局统计；`duplicate_members`、`duplicate_issues`、`duplicate_outcomes`、`duplicate_confirmation` 各返回最多 25 项。组摘要仅含代表文件，不夹带所有成员。`scanId` 校验当前会话；前端请求序号排除旧响应。
- `duplicate_selection` 在后端切换、清空或按规则替换勾选。确认查询及 `trash_duplicates` 携带勾选版本；过期请求在任何文件操作前拒绝。成功项从结果移除，有效失败项保留勾选，变化组锁定并清除其勾选。
- `duplicate_preview`、`reveal_duplicate`、`copy_duplicate_path` 只通过查重会话的文件 ID 和身份快照访问文件。预览复用媒体库的图片、HEIF、视频首帧和实况封面解码器；复用 128 项／24 MiB 的会话内 LRU 预览缓存，读取缓存前也校验文件。缩略图最多并发 3 项，大图最多 1 项，解码时释放结果会话锁。

## 性能与规模对照

显式运行：

```bash
cargo test --manifest-path src-tauri/Cargo.toml --offline --lib duplicates::tests::benchmark_sampling_against_full_hash_pipeline -- --ignored --nocapture
cargo test --manifest-path src-tauri/Cargo.toml --offline --lib duplicates::tests::scans_100000_real_files_with_one_large_duplicate_group -- --ignored --nocapture
```

同一临时数据先运行不带抽样的完整哈希／逐字节管线，再运行抽样管线，并断言全部分组及成员路径一致。下表为一次开发构建运行，字节数统计实际内容读取（含比较时两侧读取），不含元数据；受系统缓存和运行次序影响，耗时不作为跨设备承诺。

| 数据 | 原管线读取 / 耗时 | 抽样管线读取 / 耗时 | 结果 |
| --- | --- | --- | --- |
| 200 个 1 KiB 文件，100 对副本 | 400 KiB / 23 ms | 400 KiB / 25 ms | 100 组一致 |
| 16 个大小相同、内容不同的 2 MiB 文件 | 32 MiB / 161 ms | 3 MiB / 17 ms | 均为 0 组；内容读取减少 90.6% |
| 16 个完全相同的 1 MiB 副本 | 46 MiB / 109 ms | 49 MiB / 134 ms | 均为 1 组；多读取 3 MiB 抽样数据 |

抽样主要帮助排除大小相同而内容不同的大文件；真实副本集仍需完整核验，因而存在额外抽样开销。未针对机械硬盘或网络磁盘作速度承诺。

另外实际创建并扫描了 100,000 个空文件：识别为一个 100,000 成员的重复组，扫描耗时 14,473 ms，内容读取为 0 字节。此测试验证目录遍历、身份核验和超大组构建；分页与确认载荷上限由独立十万成员测试验证。

## 浏览器与原生验证

在隔离 Chromium 页面中注入临时 Tauri IPC 模拟，仅供界面验证，模拟数据未写入应用代码或生产包。模型包含 30 组，其中一组 100,000 成员，长中文路径，以及超过一页的问题和处理明细。

- 验证组列表和成员页各最多 25 项，跨页往返保留手动勾选，应用规则后的全局勾选与筛选范围外提示正确。
- 验证确认明细仅加载 25 行；取消弹窗未发起清理命令，默认焦点落在取消按钮。
- 验证取消扫描后立即重扫；延迟返回旧搜索结果不会覆盖新结果，中文输入法组词期间不查询。
- 检查浅色／深色及 1440×1024、390×844 的结果、规则设置和确认弹窗，没有页面或弹窗横向溢出。预览解码、定位和剪贴板的真实路径校验另由 Rust 回归覆盖，浏览器模拟不等同于系统操作验收。

Linux GIO 原生回收站测试显式运行并通过：在项目内自动清理的临时目录设置独立 `XDG_DATA_HOME`，使用独立 D-Bus 会话，将选定副本移入真实回收站，确认保留项存在、回收站内容及信息文件正确，再通过 `gio trash --restore` 恢复并核对字节。最初在 `/tmp` 尝试时，GIO 拒绝对系统内部挂载执行回收站操作；改用项目内普通目录后通过，未使用永久删除降级。

Windows、macOS 的原生回收站及文件管理器定位、剪贴板交互，以及各平台 Tauri WebView 的真实端到端操作仍需在对应桌面环境验收。
